# CUDA Kernel Wrappers and Device Utilities

This document summarizes the components under `src/compat` and `include/compat`
that expose CUDA functionality.  The directory houses kernel wrappers and
utility classes that allow the rest of the engine to launch GPU work without
directly depending on the CUDA runtime.

## Directory Overview

`src/compat/README.md` describes the CUDA layer as consisting of kernels, wrapper classes and a small C API. The wrappers live under `core/` while kernels like `pattern_kernels.cu` and `quantum_kernels.cu` implement the compute work. Utility files such as `event.cu` and `raii.cpp` provide RAII helpers.

The README also warns that generated files such as `cmake_install.cmake` should be removed from version control.

`include/compat/README.md` lists the public headers that mirror the implementation directory. Files such as `cuda_wrapper.h`, `core.h`, `raii.h`, `stream.h` and `event.h` map to the sources in `src/compat`.

## Build Artifacts and Unused Files

- `src/compat/cmake_install.cmake` and the top level `cmake_install.cmake` were generated by CMake and have been deleted.
- `src/compat/core/core.cu` provides the `CudaCore` implementation and remains part of the build.
- The old `include/cuda` symlink has been removed. All source files now include headers from `compat` directly.

## Device Utilities

Several helpers abstract direct CUDA calls:

- `raii.cpp` implements `StreamRAII`, `EventRAII` and `DeviceBufferRAII` for automatic resource management.
- `event.cu` exposes lightweight wrappers around `cudaEvent` operations.
- `utils.cu` provides allocation helpers used by the wrappers.

## Header to Implementation Mapping

- `cuda_wrapper.h` → `core/cuda_wrapper.cu`
- `core.h` → `core/core.cu`
- `stream.h` → `core/stream.cpp` (helper struct defined inline in `stream_impl.h`)
- `event.h` → `event.cu`
- `raii.h` → `raii.cpp`
- `kernels.h` / `kernels.cuh` → `pattern_kernels.cu` and `quantum_kernels.cu`
- Memory helpers declared in `memory.h` are implemented in `raii.cpp`
- `cuda_api.cu` exposes a C interface but lacks a dedicated header.

## Duplicate or Legacy Kernels

Only one copy of `pattern_kernels.cu` and `quantum_kernels.cu` exists. `core/core.cu` contains the `CudaCore` logic and is required by the library.

## Compatibility Layer API

The CUDA wrappers present under `include/compat` expose GPU services to the rest
of the engine.  `CudaWrapper` provides a low level singleton around the CUDA
runtime, while `CudaCore` builds higher level management and kernel launch
helpers on top.  Other modules now include the headers from `include/compat`
directly and link against `sep_compat` to access GPU functionality.  The C API
in `cuda_api.cu` further allows non-C++ components to
drive kernels without depending on C++ abstractions.
