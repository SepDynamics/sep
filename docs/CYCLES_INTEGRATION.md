# Integrating Blender Cycles with SEP Engine

This document outlines the initial setup and a detailed plan for including the Blender Cycles renderer as an external component of the SEP Engine. The goal is to use Cycles as a rendering backend for the engine's mesh management system while keeping the repository lean and maintainable.

## Rationale

We aim for a clean separation between SEP's core code and any large third-party projects. Cycles will be tracked as a Git submodule under `extern/` so the main repository history stays lean and external dependencies are clearly demarcated.

## Repository Layout

- `extern/cycles/` – Git submodule tracking [blender/cycles](https://github.com/blender/cycles). All Cycles sources will reside here.
- `.gitmodules` – Records the submodule reference for `extern/cycles`.
- `.gitignore` – Updated to exclude everything under `extern/` by default, but specifically re-include `extern/cycles` and its contents so the submodule pointer and its working directory are tracked without committing the entire upstream history.
- `docs/CYCLES_INTEGRATION.md` – This document, detailing the integration process.

## Initial Setup

To get the Cycles source code into your SEP repository:

1.  **Clone the SEP repository normally.**
2.  **Add the submodule (if not already present):**
    ```bash
    git submodule add https://github.com/blender/cycles.git extern/cycles
    ```
    *Note: If you've already cloned, this step might be done by a previous setup.*
3.  **Initialize and update submodules:**
    ```bash
    git submodule update --init --recursive
    ```
    This command fetches the Cycles sources and places them under `extern/cycles/`.

## Build Considerations

The main `CMakeLists.txt` will need new targets that compile the Cycles renderer as a static or shared library. These build steps are pending and should live under `cmake/` or a dedicated `cycles` module.
The build process should aim to:

1.  Compile Cycles as a static library using its provided build scripts inside `extern/cycles`.
2.  Update the SEP CMake build to link against the resulting libraries. A dedicated `Cycles` target will be added in a later phase.
3.  Limit the Cycles build footprint by disabling unnecessary Blender options and components if possible.

## Next Steps

1.  **Library Integration** – Create CMake rules to build Cycles within the SEP project.
2.  **Mesh Bridge** – Expose a small API layer to translate SEP's internal mesh data structures into the scene and geometry representations expected by Cycles.
3.  **Rendering Pipeline** – Add a new module that drives Cycles, feeding it frames generated by the engine's simulation.
4.  **Prototyping** – Any experimental integration code should start in `/_sep/testbed/` so that unfinished features don't pollute the main production tree.

This approach keeps the Cycles code separated from SEP's core while providing a clean path for deeper integration.
