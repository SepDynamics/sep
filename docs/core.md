# Core Module Audit

This document summarizes the results of inspecting the `src/core` and `include/core` directories.

## Overview

- Checked for and removed obsolete `cmake_install.cmake` build artefacts across all modules.
- Verified public function declarations in headers.
- Reviewed `.cpp` files for unnecessary `inline` usage.

## Findings

1. **Build artefacts**
   - `cmake_install.cmake` files generated by CMake were found under multiple modules and have been removed. The one in `src/core` was a typical install script and not needed in version control. The file begins with:

     ```cmake
# Install script for directory: /sep/src/core

# Set the install prefix
if(NOT DEFINED CMAKE_INSTALL_PREFIX)
```
   - Similar files are present in other modules but were outside the scope of this inspection.

2. **Header declarations**
   - All public methods implemented in `src/core` are declared in their corresponding headers. For example, `Engine` exposes its API in `include/core/engine.h`:

     ```cpp
class Engine {
 public:
  Engine() noexcept(false);
  ~Engine();

  // Delete copy operations
  Engine(const Engine &) = delete;
  Engine &operator=(const Engine &) = delete;

  // Allow move operations
  Engine(Engine &&) noexcept = default;
  Engine &operator=(Engine &&) noexcept = default;

  // Explicit initialization and lifecycle management
  bool init(const ::sep::config::APIConfig& config);
  void run();
  void shutdown();

  void generate_probes(const ::sep::shim::vector<::sep::PinState> &inputs,
                       ::sep::shim::vector<std::uint32_t> &indices,
                       ::sep::shim::vector<std::uint32_t> &expectations,
                       std::uint64_t tick);

  void process_batch(const ::sep::shim::vector<::sep::PinState> &inputs,
                     std::uint64_t tick,
                     ::sep::quantum::QBSAResult &qbsa_result,
                     ::sep::cuda::QSHResult &qsh_result);

  // DAG accessors
  struct StateNode {
    std::uint64_t tick{0};
    float coherence{0.0f};
    bool rupture{false};
    ::sep::shim::vector<std::size_t> parents;
  };

  const ::sep::shim::vector<StateNode> &getStateHistory() const noexcept;
```
   - `MetricsCollector` and other classes follow the same pattern.

3. **Inline code**
   - Searching for the `inline` keyword in `src/core` returned no matches:

     ```
$ grep -n "inline" -R src/core
```

   - This suggests there are no unintended inline function definitions in the implementation files.

4. **Potential consolidations**
   - The metrics helpers (`allocation_metrics.*`, `tracing.*`, `prometheus_exporter.*`) already use the `sep::metrics` namespace, but the README notes future consolidation into a single module.
   - Tests include `src/core/system_hooks.h`, but the header lives in `include/core`. Updating test includes to `<core/system_hooks.h>` would avoid relying on source paths.

## Minimal file set after cleanup

After removing `cmake_install.cmake` artifacts, the following files remain as the core public and implementation units:

- **Metrics**: `allocation_metrics.*`, `metrics_collector.*`, `prometheus_exporter.*`
- **Tracing**: `tracing.*`
- **Engine management**: `engine.*`, `manager.*`, `error_handler.*`, `dag_graph.*`
- **Support headers**: `common.h`, `env_keys.h`, `system_hooks.h`, `types.h`

No legacy or duplicate implementations were found during the audit.

## Recommendations

- Remove `src/core/cmake_install.cmake` and any similar CMake install scripts from the repository.
- Update tests referencing `src/core/system_hooks.h` to include the installed header path.
- Continue consolidating metrics utilities under the `sep::metrics` namespace to reduce boilerplate.
